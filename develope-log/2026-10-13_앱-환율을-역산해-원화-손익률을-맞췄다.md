# 2026-10-13 · 토스 앱의 환율을 역산해 원화 평가액과 손익률을 맞췄다

> 확정된 기록이다. 고치지 않는다. 이날 AI(나)는 **세 번 멈추자고 했고, 세 번 다 틀렸다.**
> 사장님이 "해결방법이 있을 거다"라며 밀어붙여서 답에 닿았다. 그 과정을 그대로 적는다.

## 문제

`npm run portfolio`의 원화 숫자가 토스 앱과 달랐다. 전체 평가액이 약 2.5만 원
높았고, 종목별 손익률은 5%p까지 벌어졌다 — BAC가 우리 -14.4%, 앱 -19.2%였다.

토스 Open API는 USD 금액만 준다. 원화 필드가 있는지부터 의심했다.

## 어떻게 좁혔나

| 확인 | 결과 |
|---|---|
| `live:holdings`로 원본 응답 | **원화·환율 필드가 없다.** 우리가 안 읽는 게 아니다 |
| 11종목 USD 합계 × 환율 | 3,723.04 × 1,344.1 = 5,004,13x. **우리 계산은 맞다** |
| 앱/우리 평가금 비율 | 종목마다 **0.9938~0.9946**. 가격이 아니라 환율 하나의 문제 |
| 앱의 IWM 달러 가격 | $278.30 = API $278.28. **가격은 같다** |
| 앱 원화가를 USD로 나눠 역산 | **1,335.8원**. 환전 화면의 1,343.32와 다르다 |
| 같은 역산을 시각을 바꿔 세 번 | API 환율이 1,344.1 → 1,342.6 → 1,343.5로 움직이는 동안 앱은 **1,335.8 그대로** |

마지막 줄이 결정적이었다. 앱의 평가 환율은 실시간이 아니라 **하루 고정값**이다.

## 틀린 것 — 내가 세 번 접자고 했다

1. **"0.25원 차이니 환율 기준 차이로 보면 된다."** 앱 합계를 받아 보니 약 2.6만 원이
   벌어져 있었다. 환율 차이(930원)로는 설명이 안 됐다. 바로 정정했다.
2. **"앱이 약 1,336원짜리 별도 환율을 쓴다 → 안내 한 줄만 넣자."** 사장님이
   "좀 더 딥띵킹해보자, 해결방법이 있을 거야"라고 했다. 그 말이 맞았다.
3. **"팔 때 환율 -0.55%"로 추정해 두 줄 표시를 넣었다**(`d148138`). 오늘은 1,000원
   안쪽으로 맞았지만 **틀린 모델**이었다. 실시간 환율에서 스프레드를 뺀 값이 아니라
   고시된 기준환율이 하루 고정으로 쓰이는 것이었다. 환율이 크게 움직이는 날엔 그
   폭만큼 어긋난다.

## 답이 나온 경로

**GPT에게 공식 자료 조사를 시켰다.** `TOSS_APP_CHECK/reference/`에 토스 공식 FAQ
(#3557·#3551·#3721)가 정리돼 있었다.

- 해외주식 원화 평가는 **서울외국환중개 기준환율**(영업일 8시 40분 고시, 하루 고정).
- 환전·금액 주문에만 실시간 **적용환율**(스프레드 포함)을 쓴다.
- Open API의 `rate`는 매수 환율, `midRate`는 은행간 매매기준율 — 둘 다 아니다.

그러면 이 값을 어디서 구하나. 서울외국환중개 사이트는 403이었고(모바일은 JS 껍데기),
**한국은행 ECOS 일별 원/달러 매매기준율(731Y001)**을 샘플 키로 조회했더니
**2026-10-13 = 1,335.8**이 나왔다. 앱에서 역산한 값과 소수점까지 같다.
10/8은 1,339.2로, 앱이 보여 준 판매 환율 1,338.99와 근접하다.

사장님이 수동 입력은 귀찮다고 해서 자동 수집으로 갔고, ECOS 인증키를 직접 발급해
`.env`의 `ECOS_API_KEY`에 넣었다.

## 원화 손익률 — 같은 방식으로 풀었다

앱 수익률은 **(기준환율 평가금 − 원화 매입금) ÷ 원화 매입금**이다.
BAC로 검증했다: (439,288 − 90,637×6) ÷ (90,637×6) = **-19.22%**, 앱과 같다.

API는 매입 시점 환율을 주지 않는다. 그래서 앱의 «1주 평균금액»(원)을
`data/krw-cost-basis.json`에 한 번 등록하는 방식으로 했다. 저장소가 공개라
gitignore되는 `data/`에 둔다.

**수량이 등록값보다 늘면 계산하지 않는다.** 새로 산 몫의 환율을 모르는데 옛 평균으로
덮으면 틀린 수익률이 나오기 때문이다. 틀린 값 대신 "갱신 필요"를 찍는다.

## 남는 것

① **BOTZ는 매입가를 등록하지 않았다.** 앱의 «1주 평균금액»을 받아야 한다.
② **봇이 사서 수량이 늘면 «갱신 필요»가 뜬다.** IWM처럼 관리 종목은 자주 걸린다.
   앱의 새 평균금액과 수량으로 그 줄을 고치는 수동 작업이다.
③ **기준환율이 바뀌는 날을 아직 못 봤다.** 10/14 8시 40분 이후 `portfolio`의
   기준환율 날짜가 10/14로 넘어가고 앱과 같이 움직이는지 확인한다.
④ **ECOS 값이 «해당일 기준환율»인지 «전일 기준환율»인지는 하루치로 못 가른다.**
   10/13 값이 오늘 오후에 이미 올라와 있었고 앱과 같았다. 날이 바뀐 아침 값으로 본다.
⑤ 손익률의 매입 환율을 앱이 «거래일 기준환율»로 쓰는지 도움말(내 투자 ?)은 확인하지
   못했다. 평균금액을 등록하는 방식이라 영향은 없지만 산식은 추정이다.

## 이날 배운 것

**답이 없다고 접는 순간이 가장 비쌌다.** API에 원화가 없다는 사실에서 «불가능»으로
건너뛰는 데 한 걸음이면 됐다. 실제로는 앱 숫자에서 환율을 역산했고, 그 환율이
**공개된 기준환율**이라는 것을 공식 FAQ가 확인해 줬고, 같은 값이 **무료 공공 API에
있었다.** 세 걸음 다 «해결방법이 있을 거야»라는 한마디 뒤에 있었다.

사장님은 이 하나를 두고 앱 숫자와 우리 숫자를 여러 번 대조했고, 내가 틀릴 때마다
다시 물었고, 다른 AI에게 공식 자료까지 조사시켜 왔고, ECOS 키 발급까지 직접
마쳤다. AI는 계산과 코드를 맡았고, **어디서 멈추지 않을지는 사람이 정했다.**
