## 0. 이 결정에 앞선 대화

시드를 10만원에서 100만원으로 올릴지 검토했고, **올리지 않기로 했다.**
근거는 산수다(아래 §4). 사용자는 대학생이고 연말 실거래 전환을 목표로 하므로
10만원을 유지한 채 실거래 배관을 만드는 쪽이 낫다고 판단했다.

## 1. 켜기 직전에 나온 것 — 문턱이 보유액 기준이 아니다

`develope-log/2026-08-07_밴드폭-확정과-방향비대칭.md` §4의 채택 근거 셋 중
하나가 교차점 공식이었다.

> 교차 비중 = 밴드 / (배수 − 1)
> 배수 2에서만 교차점이 밴드와 같은 5%

코드를 열어보니 비교 대상이 보유액이 아니라 **초과분**이었다.

```js
// paper-engine.js:347-356
function exitBand(policy, equityUsd, targetValueUsd) {
  const absoluteUsd = (Number(policy.rebalanceExitBandRate) || 0) * equityUsd;
  const driftUsd = policy.targetDriftCap === null
    ? Infinity
    : Number(policy.targetDriftCap) * targetValueUsd;   // ← 목표 × 배수
  return Math.max(policy.minOrderUsd, Math.min(absoluteUsd, driftUsd));
}

// paper-engine.js:268
if (roundUsd(currentValue - targetValue) < exitBand(...)) continue;   // ← 초과분과 비교
```

즉 매도 조건은 `보유 − 목표 ≥ 목표 × 배수` → **`보유 ≥ 목표 × (배수+1)`** 이다.
배수 2는 "보유가 목표의 2배"가 아니라 **3배**다.

교차점도 달라진다.

| | 문서가 가정한 의미 | 코드의 실제 의미 |
|---|---|---|
| 매도 조건 | 보유 ≥ 목표 × 배수 | 보유 ≥ 목표 × (배수+1) |
| 교차점 | 밴드 / (배수−1) = **5%** | 밴드 / 배수 = **2.5%** |

## 2. 실측 — 발동 경계는 목표 2% 부근

보유를 6%로 세운 뒤 되돌림 목표를 바꿔가며 40거래일을 밟았다.
`cap 끔`은 `TARGET_DRIFT_CAP=off`, `cap=2`는 채택값이다.

| 점수 | IWM 목표 | cap 끔 | cap=2 | 판정 |
|---|---|---|---|---|
| 0.156 | 1.60% | 6.00% | **1.60%** | 목표 안착 |
| 0.200 | 2.00% | 6.00% | 6.00% | 갇힘 |
| 0.250 | 2.50% | 6.00% | 6.00% | 갇힘 |
| 0.300 | 3.00% | 6.00% | 6.00% | 갇힘 |
| 0.400 | 4.00% | 6.00% | 6.00% | 갇힘 |

교차점 계산은 2.5%지만 실측 경계는 2% 부근이다. 보유가 6%로 고정된 이 경로에서는
`(0.06 − w) ≥ 2w` → `w ≤ 2%`이기 때문이다. 교차점은 "이 아래에서 상대 규칙이
절대 밴드보다 좁아지는 지점"이고, 실제 발동은 그보다 더 안쪽에서 일어난다.

**08-05 IWM은 목표가 1.6%로 되돌아와 간신히 이 안에 들었다.**
점수가 0.156이 아니라 0.20으로 되돌아왔다면 고쳐지지 않았다.

## 3. 그래도 채택하는 이유

채택 근거는 셋이었고 그중 둘이 그대로다.

| 근거 | 상태 |
|---|---|
| 단위 테스트가 확정한 효과 (잔여물 → 목표 1.6% 안착) | **유효** — 좁은 버전을 잰 것 |
| 백테스트 가격표 CAGR 연 0.152%p | **유효** — 좁은 버전을 잰 것 |
| 교차점 = 밴드/(배수−1) = 5% | **틀림** — 실제 2.5% |

세 번째는 "왜 1.25가 아니라 2인가"를 설명하던 논거인데, 그 판정 자체는 실측이
따로 뒷받침한다 — 2가 1.25를 CAGR·회전율·체결·부호일치 전 축에서 이겼다.
정정된 식으로 봐도 1.25의 교차점은 4%로 여전히 2(2.5%)보다 넓다. **결론의 방향은
바뀌지 않고, 바뀌는 것은 "얼마나 덮는가"다.**

백테스트에 물은 질문이 `"고치면 얼마를 잃는가"`였다는 점도 그대로다. 잰 대상이
좁은 버전이었으므로 그 답은 좁은 버전에 대해 정확하다.

**넓은 버전(교차점 5%)은 측정한 적이 없다.** `exitBand()`를 `(배수−1) × 목표`로
바꾸면 되지만, 재기 전에 바꾸지 않는다 — §6의 규율이다.

## 4. 곁가지 — 시드를 올려도 래칫은 안 풀린다

"시드가 작아서 부분 정리가 안 된 것 아닌가"를 먼저 확인했다. 아니었다.

```
초과분 = (보유 6.0% − 목표 1.6%) = 4.4% × 자산
밴드   = 5.0% × 자산
```

**둘 다 자산에 비례한다.** 4.4% < 5%는 자산과 무관하다. $67이든 $67,050이든
똑같이 갇힌다. 래칫은 금액 문제가 아니라 비율 문제이고, 그래서 해법도
`TARGET_DRIFT_CAP`이지 증액이 아니다.

$1 최소 주문이 밴드를 왜곡하는 범위도 함께 쟀다.

| 밴드율 | $1 바닥이 걸리는 자산 | $67.05 시점 실효 |
|---|---|---|
| 1% | $100 미만 | 1.49% (왜곡) |
| 2% | $50 미만 | 2.00% |
| **5%** | **$20 미만** | **5.00%** |
| 10% | $10 미만 | 10.00% |

**운영값 5%는 처음부터 왜곡되지 않았다.** 08-07 밴드 폭 실험에서 흠으로 적어둔
것은 비교 대상이던 1% 변형에만 해당하고, 그것도 표본 14.7년 중 앞 5.1년뿐이다
(자산이 $100을 넘으면 풀린다). 1%를 진짜 1%로 만들면 밴드가 더 좁아져 회전율이
더 늘므로, "회전율 2배"라는 기각 근거는 오히려 강해진다. **결론은 안 바뀐다.**

## 7. 같은 날 함께 연 것 — 익스포저 상한

사용자가 전략 방향을 다시 잡았다. **"낙폭을 줄이는 건 알겠는데, 결국 스스로
시드를 불리는 시스템이어야 한다"**는 것이었다.

숫자로 보면 시스템은 이미 불어난다 — 20년 연 6.0%다. 문제는 속도다. 같은 기간
VTI 매수후보유가 연 12%(MDD 56.7%)다. **복리 속도의 절반을 내주고 낙폭 절반을
샀다.** "덜 잃으면 결국 더 번다"는 이 표본에서 성립하지 않았다. CAGR이 이미 그
효과까지 반영한 숫자인데 낮기 때문이다.

기계적 출처를 찾았다. `market-signal.js:124`:

```js
exposureMultiplier = clamp(round(volTarget / annualizedVol), minExposure, 1);
//                                                                        ^ 상한 1
```

**변동성 관리가 한 방향으로만 동작해 왔다.** 시끄러우면 줄이고, 조용해도 기본
배분 이상으로는 늘리지 않는다. 그래서 아낀 낙폭이 현금으로만 쌓이고 수익으로
돌아오지 않는다.

`maxExposure` 손잡이를 뺐다. **기본값 1이라 운영 동작은 그대로다.**
`--compare exposure`도 함께 넣었다. 정적 70/30·90/10을 같은 표에 둬서
(MDD, CAGR) 기준선을 만든다 — 변형이 그 선 위에 있어야 채택이다.

### 실효 범위가 좁다는 것을 먼저 알아야 한다

NEUTRAL 기본 배분이 주식 90%(VTI 70 + SCHD 20)다. 배수 1.111에서 주식 합이
100%에 닿고, 그 위로는 상한을 올려도 배분이 같다. 레버리지가 없기 때문이다
(`scaleForExposure()`가 100%에서 눌러 담는다).

**이 손잡이로 살 수 있는 노출은 최대 +11%p다.** 합성 900일 스모크에서도 상한
1.4와 1.6이 1.2와 사실상 같았다. 더 원하면 배분표를 손대야 하고, 그것은 다른
결정이다.

### 아직 안 쟀다

로컬에 실데이터 캐시도 TwelveData 키도 없다. 합성 경로로 배선만 확인했고,
**판정은 하지 않았다.** 판정 기준은 결과를 보기 전에 `STRATEGY.md` §5-0에
적어뒀다.

안 나타났고, CAGR 표에도 안 나타났다.** 코드를 읽어야 나왔다.

이 시스템에서 결정론적 성질은 표본이 아니라 재현으로 증명된다고 여러 번 적었는데,
같은 이유로 **결정론적 성질의 오류도 표본이 아니라 코드 읽기로만 잡힌다.**
백테스트가 통과했다는 것은 "그 설정이 그만큼의 대가를 치른다"는 뜻이지
"그 설정이 의도한 일을 한다"는 뜻이 아니다.
